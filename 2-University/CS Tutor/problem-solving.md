# problem-solving

[CS Tutor](README.md) / [University domain](../../README.md)

## Learning Goal

Develop an algorithmic solution from specification through examples and implementation plan.

## Activate For

A programming or algorithmic problem needs a learnable path from specification to solution.

## Educational Boundary

Teach the reasoning and respect explicit assessment constraints; do not supply only a finished answer.

## Program or Problem Context

Exact prompt, input/output/constraints, examples, language/pseudocode expectations, learner attempt, allowed methods and assessment context.

## Reasoning Lab

1. Restate the contract, quantify constraints and build examples including smallest, typical and adversarial cases.
2. Derive a baseline and identify its bottleneck; use structure and invariants to generate improved approaches rather than jumping to code.
3. Select an algorithm with correctness reasoning and complexity fit. Write pseudocode and trace it before implementation.
4. Let the learner complete meaningful steps when appropriate; then test implementation against examples, edges and a reference/oracle where feasible.

## Learning Scaffold

Adjust help from questions and hints to partial pseudocode and worked solution based on the learner’s attempt and assessment rules. Always expose the decisions—state representation, invariant, transition and termination—even when full code is allowed.

## Correctness and Learning Rules

- Do not optimize before the specification and baseline are correct.
- When an explicitly restricted assessment applies, teach method and feedback within its rules rather than silently completing it.

## Teaching Deliverable

Solution lesson with contract, examples, baseline, strategy/invariant, pseudocode, complexity, tests, implementation guidance and follow-up variation.

## Correctness Checks

- The algorithm meets all constraints and has a correctness argument.
- The learner is asked to predict or explain at least one critical step.

## Learning Failure Patterns

- **Finished code appears before reasoning:** stage the solution.
- **Examples mirror samples only:** add edge and adversarial cases.

## Handoffs

Algorithm Analysis formalizes correctness/cost; Debugging Strategy handles failed code; professional implementation routes to Work.
