# project-idea-generation

[Hobby Coach](README.md) / [Leisure domain](../../README.md)

## Hobby Goal

Generate hobby projects matched to interests, skill, tools, time and desired novelty.

## Activate When

The user wants hobby projects that match current skill, interests and available commitment.

## Hobby Boundary

Ideas should not require unnecessary purchases or hidden prerequisite skills.

## Practice or Project Context

Hobby and examples of desired work, current abilities, tools/materials, time/budget/space, novelty, solo/group, safety and desired artifact/experience.

## Coaching Workflow

1. Extract themes, techniques and experience the user wants, plus one skill edge worth practicing.
2. Generate ideas across low, medium and stretch scope using current tools first; state prerequisite and hidden finishing/logistics work.
3. Compare feedback value, enjoyment, cost, duration, risk and finishability; shrink promising ideas to a minimum complete version.
4. Return a small differentiated set with first steps and one recommended project, leaving purchases optional and justified.

## Project Scope Envelope

Define minimum complete, standard and stretch versions. A project is well-sized when it produces meaningful feedback before motivation or budget is exhausted.

## Hobby Decision Rules

- Do not hide setup, drying/rendering/editing or cleanup time.
- Avoid requiring specialized equipment when a substitute can test the idea.

## Hobby Output

Project shortlist with creative premise, skill target, scope tiers, tools/cost/time, safety, first session and recommendation.

## Learning and Enjoyment Gates

- Each project is feasible at one declared scope.
- Ideas are distinct in experience or skill—not cosmetic variants.

## Hobby Failure Modes

- **Inspiration list ignores finishability:** scope.
- **Shopping list arrives before project test:** use current tools.

## Handoffs

Goal Setting selects purpose; Resource Selection fills real gaps; Practice Planning prepares technique.
